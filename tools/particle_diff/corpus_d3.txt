# Diablo III `.app` corpus for the D3 render gate (render-diff.ps1 -D3).
#
# Paths are relative to C:/Projects/WhiteoutLib/Corpus/D3. These are
# appearances, not actors: an `.app` is the model and needs nothing else, which
# is what lets this arm run against an extracted tree with no CASC install. The
# `.acr` route — look picking and the AnimSet — needs the storage, and belongs
# to a run against the install rather than to this list.
#
# Chosen for spread rather than for count, because a golden set whose entries
# are byte-identical to each other proves nothing (the trap that made the first
# -M3Anim recording vacuous):
#
#   * two player classes, one heavily skinned and one lighter
#   * a monster with a different bone count
#   * a static prop with NO skeleton at all, which is 63% of the corpus and
#     exercises the boneless path GetSkinWeights returns empty for
#   * an appearance with more than one look, so the look index is doing work
#
# Add to this list when a phase makes a claim these do not exercise; do not add
# to it to make a number bigger.

# entries whose materials carry more than one texture layer, a per-look
# visibility rule, or a UV animation — the three things that were being read
# off the wrong field.
#
#   Tyrael      three bodies (Stranger, Restored, skeleton) and two looks; drew
#               all three at once, which put a skull through his head. NOTE that
#               at look 0 only `A_normal_mat` survives the look bit, so his
#               CAPE is not in this arm at all -- the two-sided cloth work is
#               covered by the four classes and SkeletonKing instead.
#   Imperius    a four-layer scrolling wing material; the diffuse is type 1 and
#               an arbitrary layer was being bound in its place.
#   x1_Malthael four wing layers, NONE of which is type 0 — so under the old
#               field reading his wings bound no texture at all.
#
# NOTE (corrected 2026-08-28): this arm passes no `--draw-trace-game`, but the
# viewer's FileContentProvider finds the installed games by itself, so the
# ShaderMap -> Shaders -> RenderPass half (blend, cull, depth write, alpha
# reference) DOES resolve here. The note that used to stand in this place said
# the opposite. What settled it: `twoSidedPair` is read only inside
# `if (st.resolved)`, and turning it on moved the psoKey of five of the ten
# entries below (D3_MATERIAL_DESIGN.md 2.3). So a machine with no Diablo III
# install records different baselines from one that has it -- which is the real
# caveat, and a stronger reason to keep `d3_surface_table_test`'s `[install]`
# cases than the one this note used to give.
