# Track C — StarCraft II / Heroes of the Storm `.m3` PARTICLE corpus
# (SC2_PARTICLE_PLAN.md §5, the -M3Particle render-diff arm).
#
# Paths are relative to C:/Projects/WhiteoutLib/Corpus, same root as
# corpus_m3.txt. Every line is a carrier CONFIRMED with
# `--draw-trace-particle-list`, which prints the desc the loader registered —
# version, shape, velocity type, instance type, analytic/euler, slots, squirt
# keys, surface, flipbook UV, and how many particles are alive after the
# settle. Picked by content, never by filename.
#
# The baselines are PROGRESSIVE, like -M3Anim's: every phase of the plan
# legitimately changes what an SC2 emitter draws, so the commit that
# re-records has to name the phase. The vacuity anchor is the `sc2par=` count
# in the `[dtrace]` line — zero means the M3 producer never drew a particle
# and the run proved nothing, however stable its golden.
#
# Two things the X2 survey CORRECTED about the provisional list in §5:
#
#   * `ZealotWeaponImpact` and `Reentry_Fire` are instance type 1 (Tail) and
#     `Smoke_Battle` is on the Euler path — none of the three is an X3 case,
#     though all three now LOAD (an effect-only `.m3` with no `REGN` used to
#     be refused outright). They stay in as X4 carriers.
#   * `GenericImpactSmear` emits only on a squirt crossing, so it holds zero
#     particles until X5 wires that. It is the smallest squirt case there is,
#     which is why it stays here rather than being swapped out.
